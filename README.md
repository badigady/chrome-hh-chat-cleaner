# hh — чистка чатов (расширение Chrome)

Расширение **само, в фоне** покидает ненужные чаты hh.ru: без кнопок и без
панели. Единственное, что вы увидите, — всплывающая плашка в правом верхнем углу
страницы с результатом обработки. Плашка исчезает сама: зелёная «не найдено
чатов для покидания» — через 1 секунду, красная «Покинуто N чатов» — через
5 секунд. Установил, открыл чаты — дальше оно работает незаметно.

Покидаются чаты **ровно по двум признакам** и только по ним:

| # | Признак | Чем определяется | Запросов |
|---|---------|------------------|---------:|
| 1 | **Отказ** | `negotiation_topics[…].currentApplicantState === "DISCARD"` | 0 |
| 2 | **Вакансия в архиве** | у объекта вакансии **есть ключ** `archived` | 0 |

Оба признака лежат прямо в ответе списка чатов: расширение использует только
данные перехваченного ответа — никакого повторного GET списка и никаких других
сетевых вызовов, кроме самого покидания.

Ничего больше не проверяется: ни даты последнего сообщения, ни того, кто кому
отвечал, ни «как давно работодатель молчит». Никакой оценочности.

## Только отклики

Рассматриваются **только** элементы списка с `type === "NEGOTIATION"` —
переписка по отклику на вакансию. Прочее не трогается никогда:

- `COMMON` — переписка без вакансии (подтип `WITHOUT_VACANCY`);
- `SUPPORT` — обращение в поддержку.

Живая проверка 2026-10-09: из 915 элементов — `NEGOTIATION` 912, `COMMON` 2,
`SUPPORT` 1. У `COMMON`, как и у отклика, есть операция `LEAVE_CHAT`, поэтому
фильтр по типу — не формальность. Элемент с незнакомым или отсутствующим
`type` не рассматривается: незнакомое — значит «не уверен».

## Правило, которому подчинено всё

**Нет полной уверенности, что чат можно покинуть, — чат не покидается.**

- форма значения `archived`, отличная от наблюдённой → чат не трогаем;
- `type` не `NEGOTIATION` → чат не трогаем;
- ошибка чтения списка или нечитаемое тело ответа → пачка не обрабатывается,
  чаты не покидаются;
- ошибка сети при покидании → прерываемся, неотправленные чаты остаются
  нетронутыми.

Признак вне таблицы признаков читается как «не уверен», а не как «можно
покидать». Поэтому незнакомое поведение никогда не приводит к покиданию.

## Как это работает

Расширение стоит на всех страницах `hh.ru`, но действует **только** на `/chat*`.

1. Работает **только при загрузке страницы чатов**. Никаких слежений за адресом,
   событиями прокрутки и мутациями DOM — реагируем исключительно на загрузку
   очередной пачки (по 20 чатов), которую сайт сам запрашивает:

   - **вход на страницу чатов** — сайт загружает первую пачку, расширение
     перехватывает ответ и обрабатывает её;
   - **догрузка при прокрутке** — сайт подгружает следующую пачку, расширение
     реагирует и обходит уже её.

   Загрузка страницы ловится **перехватом запроса списка** самим сайтом
   (`GET /chatik/api/chats`): расширение перехватывает XHR/fetch и читает тело
   ответа — без повторного запроса. Если первая пачка пришла не через XHR/fetch
   (через SSR), расширение делает ровно один свой fetch к списку.

2. За одно срабатывание обрабатывается **одна** пачка — та, что загрузил сайт.
   Если предыдущая пачка ещё обрабатывается, новая встаёт в очередь и будет
   обработана после окончания текущей.

3. Ненужные чаты покидаются:
   `POST https://chatik.hh.ru/chatik/api/bulk/leave` с `{"chatIds": [...]}`
   пачками по **20** (как делает сам сайт), с паузой 700 мс между чанками.
   Счёт «покинуто» идёт по полю `applied` в ответе сервера — расширение
   доверяет ответу, список не перечитывает.

4. После обработки пачки — ровно одна плашка:
   - **красная** «Покинуто N чатов» — если покинут хотя бы один чат;
   - **зелёная** «не найдено чатов для покидания» — если ни один.

   Это единственный интерфейс расширения: ни кнопок, ни панели, ни системных
   уведомлений.

Никакого локального списка «уже покинутых» расширение не ведёт: состояние не
накапливается между пачками — каждый перехваченный ответ обрабатывается сам по
себе, а покинутый чат просто исчезает из последующих ответов сайта.

## Про признак 2: почему проверяется ключ, а не значение

Значение приходит как `{"@hidden": false}` и как булево не читается. Но
присутствие самого ключа — точный признак архива.

Проверено пересечением с серверной правдой на **914 вакансиях**: ключ `archived`
есть ровно у одной вакансии, и это ровно та, которую мобильный API помечает
`archived: true`. Расхождений — **ноль**.

Прежний прокси `closedForApplicants` давал **26 ложных срабатываний и ноль
точных**, поэтому не используется.

## Доступ и безопасность

- Расширению **не нужен** ни пароль, ни `refresh_token`, ни какой-либо секрет.
  Расширение работает на куках текущей сессии hh.ru — запросы уходят с теми же
  куками, что и у сайта.
- Расширение не обращается к мобильному API `api.hh.ru` и не читает
  `~/.hh/config.json`.
- Ничего не отправляется на сторонние сервисы. Только `hh.ru` и `chatik.hh.ru`.
- Покидание необратимо: вернуть чат может только новое приглашение от
  работодателя. Поэтому расширение покидает **только** чаты с признаками из
  таблицы выше и ничего больше.
- Полная формулировка — в [PRIVACY.md](PRIVACY.md).

## Установка

Расширение устанавливается вручную, в режиме разработчика (Chrome Web Store
публикация запланирована — минимально достаточная обвязка уже в репозитории,
манифест версии 1.1.0).

1. `chrome://extensions` → включить «Режим разработчика».
2. «Загрузить распакованное расширение» → указать корневой каталог
   репозитория (в нём лежит `manifest.json`).
3. Открыть `https://hh.ru/chat` и войти в аккаунт. Дальше оно работает само.

### Обновление

```sh
git pull
# или
git fetch && git reset --hard origin/main
```
Затем `chrome://extensions` → «Обновить».

### Удаление

`chrome://extensions` → «Удалить».

### Требования

- Chrome (MV3 + `world: "MAIN"` — Chrome 111+, поддерживающий `"world": "MAIN"`
  в content scripts);
- Node.js — **опционально**, только для тестов и проверки типов.

## Конфигурация

У расширения нет пользовательских настроек. Диагностический лог в консоль
страницы управляется флагом `DEBUG` (`cleaner.js:82`, сейчас `true` — поставьте
`false`, чтобы выключить).

## Диагностика

Ход работы пишется в консоль страницы (F12 → Console) с префиксом `[hh]`:
запуск и мир (главный/изолированный), перехваченные ответы списка, количество
чатов к покиданию, результат покидания.

## Что показано на живом аккаунте (2026-10-09)

> Числовые id и названия вакансий/компаний ниже обезличены — заменены на
> синтетические той же формы, чтобы не публиковать реальные данные аккаунта.

Полный обход самих файлов расширения в браузере, на живом аккаунте:
46 страниц, 915 элементов из 916, **912 откликов**
(`COMMON` 2, `SUPPORT` 1). Автоматический проход, **без единого нажатия**,
покинул **3 чата**:

| id | Вакансия / компания | Признак |
|---|---|---|
| `5000000002` | Должность B, Компания B | отказ |
| `5000000003` | Должность C, Компания C | вакансия в архиве |
| `5000000009` | Должность F, Компания F | вакансия в архиве |

Третий чат — самый показательный. На разведке за минуты до прохода целей было
две. В 19:29:28 работодатель закрыл вакансию (в чате: «уже закрыли эту
позицию»), у вакансии появился ключ `archived` — и через 15 секунд проход это
увидел и покинул чат сам. Признак появился в аккаунте буквально на глазах, и
человек не участвовал ни в чём.

Покинуто по ответу `/bulk/leave`: `applied` = 3 id, чаты из списка исчезли
(`found` 916 → 913). Признак третьего чата подтверждён детализацией
`GET /chatik/api/chat_data?chatId=5000000009`: у вакансии `700000006` есть
`archived: {"@hidden": false}`, тема — в состоянии `RESPONSE` (то есть сработал
именно признак 2, а не отказ).

### Что вскрыла приёмка

Обе прежние неисправности были одного класса: **состояние накапливалось в одном
месте, а читалось в другом**.

1. Ресурсы каждой страницы списка **перезаписывались** следующей страницей.
   В решении оставались только ресурсы **последней** страницы: 15 тем, 15
   вакансий и 15 заголовков из 915. Из-за этого признаки молчали — расширение
   показывало «подходящих чатов не найдено», то есть **ложный вывод о том, что
   чистить нечего**. До слияния: 0 находок, после: 2.
2. `reasons` вычислялся в двух местах, и чат с признаком получал `undefined`,
   на чём всё падало (`undefined.length`).

Второй дефект опаснее первого: он не падал, а тихо давал неверный ответ.
Оба закрыты тестами в `test/verdicts.test.js`.

### Сверка с мобильным API

Признак 1 совпал полностью. Признак 2 на прокси `closedForApplicants` разошёлся
на всех 26 срабатываниях: ни одна из этих вакансий не архивна. Правило «есть
ключ `archived`» совпало с серверной правдой на всех 914 вакансиях и дало ноль
ложных срабатываний.

### Отдельно о покидании

Покидание считается по полю `applied` в ответе `POST /bulk/leave`:
`applied` — это «id принят API». Повторный POST того же чата возвращает `200`
с тем же телом (идемпотентность). Расширение не перечитывает список для
верификации.
